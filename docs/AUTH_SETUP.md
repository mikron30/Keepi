# Keepi authentication setup

Keepi currently supports:

- Email + password
- Google
- Apple (shown on iPhone/iPad/macOS and Web)
- Password reset
- Sign out

## Firebase providers

Open Firebase Console for the dedicated Keepi project:

```text
Authentication > Sign-in method
```

Enable:

1. Email/Password
2. Google

The app already contains the UI and Firebase Auth code for both providers.

## Apple

The Keepi iOS project contains the Sign in with Apple entitlement and the Flutter code uses Firebase's `AppleAuthProvider`.

Before an App Store/iPhone release, Apple sign-in also requires:

- An Apple Developer account
- Sign in with Apple enabled for the Keepi App ID
- Apple provider configured in Firebase Authentication with the Apple credentials requested by Firebase

## Google on native mobile

Web sign-in uses Firebase Auth popup directly.

For native Android/iOS, Keepi uses the official `google_sign_in` Flutter plugin. Android release builds will also need the correct SHA certificate fingerprint registered in Firebase. iOS Google sign-in requires the Google client ID and reversed client ID configuration from the current `GoogleService-Info.plist`.

## Web Firebase configuration

`publish_keepi_web.ps1` reads the local `lib/firebase_options.dart` generated by FlutterFire and passes the Web Firebase values to the release build using Dart defines. Project-specific generated Firebase configuration remains out of Git.
